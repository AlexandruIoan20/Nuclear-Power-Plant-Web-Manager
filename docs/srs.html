1. Introducere

1.1 Scop

Acest document specifică cerințele software pentru platforma web Nuclear Power Plant Web Manager, un sistem integrat de gestionare a centralelor nucleare, incluzând înregistrarea centralelor, studiul de fezabilitate, administrarea reactoarelor, monitorizarea în timp real a senzorilor, generarea de alerte și statistici, precum și administrarea utilizatorilor. Sistemul este conceput pentru a fi utilizat de ingineri nucleari, operatori și administratori.

1.2 Convenții

În acest document, cuvântul „sistem" se referă la aplicația Nuclear Power Plant Web Manager. Cerințele funcționale sunt notate cu RF- urmat de un număr, iar cele nefuncționale cu RNF-. Termenii „utilizator" și „operator" se referă la persoanele fizice care interacționează cu sistemul.

1.3 Public țintă

  • Dezvoltatori — pentru implementarea și mentenanța sistemului
  • Ingineri nucleari / operatori — utilizatori principali ai platformei
  • Administratori — gestionarea utilizatorilor și aprobarea centralelor
  • Evaluatori academici — pentru verificarea conformității cu cerințele proiectului

1.4 Domeniu de aplicare

Sistemul acoperă următoarele domenii funcționale:

  • Înregistrarea și autentificarea utilizatorilor
  • Gestionarea centralelor nucleare (date de bază, geologice, tehnice)
  • Studiul de fezabilitate cu algoritm decizional (NSVI)
  • Procesul de aprobare a centralelor de către administratori
  • CRUD pentru reactoare și senzori
  • Monitorizare în timp real a senzorilor via SSE
  • Simulator de senzori cu comportament fizic per tip de reactor
  • Sistem de alerte și notificări (email, notificări in-app)
  • Statistici și diagrame (D3.js)
  • Harta interactivă a centralelor (Leaflet.js)
  • Import/export date (JSON individual, JSON batch, CSV, ZIP)
  • Flux RSS pentru centrale
  • Administrarea utilizatorilor

1.5 Referințe

  • IEEE Std 830-1998 — IEEE Recommended Practice for Software Requirements Specifications
  • Documentația PHPMailer v6.x
  • Documentația PostgreSQL 15
  • Documentația D3.js v7

2. Descriere generală

2.1 Perspectiva produsului

Nuclear Power Plant Web Manager este o aplicație web de sine-stătătoare, construită pe o arhitectură client-server fără framework-uri. Sistemul este compus din:

  • Backend: PHP 8.4 cu Apache, PostgreSQL 15, arhitectură stratificată (Controller → Service → Repository → Entity)
  • Frontend: HTML5, CSS3, JavaScript Vanilla (ES Modules), Leaflet.js, D3.js
  • Infrastructură: Docker Compose (5 servicii: web, simulator, aggregator, cleanup, PostgreSQL)

Sistemul comunică printr-o interfață REST API cu protecție CSRF (token în sesiune) și autentificare bazată pe sesiuni PHP. Fluxul de date în timp real este realizat prin Server-Sent Events (SSE).

2.4 Constrângeri

  • Nu se utilizează framework-uri web (nici client, nici server)
  • Baza de date: PostgreSQL 15
  • Serviciul web: Apache 2.4 + mod_php 8.4
  • Containerizare: Docker Compose
  • Responsive design
  • Protecție împotriva SQL injection, XSS, CSRF

2.5 Ipoteze și dependențe

  • Se presupune existența unei conexiuni stabile la rețea
  • Dependențe externe: serviciu SMTP (Mailtrap), API de geocodare (OpenStreetMap/Nominatim)
  • Dependențe CDN: D3.js v7, Leaflet.js 1.9.4

3.2 Cerințe de interfață externă

3.2.1 Interfață utilizator

  • Interfață web responsive, cu temă întunecată
  • Navigare prin bara de navigare superioară cu link-uri diferențiate per rol
  • Formulare multi-pagina cu wizard pentru crearea centralelor
  • Tabel interactiv pentru listarea centralelor, reactoarelor și senzorilor
  • Diagrame D3.js pentru statistici
  • Hartă Leaflet.js cu markeri pentru centrale
  • Notificări tip toast pentru alerte

3.2.2 Interfață API

  • API RESTful cu răspunsuri JSON
  • 67 de rute API documentate în index.php
  • Protecție CSRF prin token în header
  • Autentificare prin sesiuni PHP cu cookie SameSite=Lax
  • CORS configurat pentru originile locale (localhost:5500, localhost:8081)

3.2.3 Interfață cu servicii externe

  • SMTP prin PHPMailer (Mailtrap pentru dezvoltare)
  • API de geocodare OpenStreetMap/Nominatim pentru completare coordonate
  • CDN: D3.js v7, Leaflet.js 1.9.4

3.3 Cerințe de performanță

  • RNF-01: Stream-ul SSE trebuie să actualizeze valorile senzorilor la maxim 3 secunde
  • RNF-02: Simulatorul trebuie să proceseze toate reactoarele într-un ciclu de 3 secunde
  • RNF-03: Agregarea măsurătorilor orare trebuie realizată la fiecare 60 de secunde
  • RNF-04: Sistemul trebuie să suporte minim 10 utilizatori concurenți
  • RNF-05: Timpul de răspuns pentru API-uri CRUD trebuie să fie sub 500ms

3.4 Cerințe de securitate

  • RNF-06: Autentificare obligatorie pentru toate acțiunile exceptând login, register și rutele publice
  • RNF-07: Protecție CSRF prin token de sesiune pentru toate operațiile non-GET
  • RNF-08: Role-based access control (ADMIN, ENGINEER, OPERATOR)
  • RNF-09: Prevenire XSS prin escaparea output-ului HTML
  • RNF-10: Prevenire SQL injection prin PDO prepared statements
  • RNF-11: Parole stocate hash (bcrypt implicit)
  • RNF-12: Cookie-uri de sesiune cu flag httponly și SameSite=Lax

3.5 Atribute de calitate

  • Disponibilitate: Sistemul trebuie să fie disponibil 24/7 cu restart automat al containerelor
  • Mentenabilitate: Arhitectură stratificată cu separarea responsabilităților (Controller → Service → Repository)
  • Portabilitate: Containerizare Docker, deploy pe orice sistem cu Docker Engine
  • Fiabilitate: Simulatorul folosește Observer Pattern pentru notificări, fără pierderi de evenimente
  • Uzabilitate: Interfață intuitivă cu ghidare pas cu pas pentru crearea centralelor

A.2 Diagrama arhitecturală (C4 Context)

Sistemul se încadrează în arhitectura C4 la nivelul Context și Container:

  • Context: Utilizatori (Engineer, Operator, Admin) → Sistem Nuclear Power Plant Web Manager → Servicii externe (SMTP, OpenStreetMap, CDN)
  • Containere: Frontend Web (HTML/CSS/JS) → Backend API (PHP/Apache) → Baza de date (PostgreSQL) + Servicii suport (Simulator, Aggregator, Cleanup)

A.3 Diagrama ER (nivel înalt)

Tabelul central power_plants se leagă la:

  • basic_data (1:1)
  • geological_data (1:1)
  • technical_data (1:1) → reactor_plant_data → reactor_schema
  • reactor (1:N) → reactor_sensors (1:N) → sensor_readings (1:N)
  • measurements (1:N per reactor) și measurements_hourly
  • alerts (1:N per plant)
  • feasibility_reports (1:N)
  • control_rods (1:N per reactor)
